# Resident charters

Resident behavior is file-backed. A collaboration prompt supplies identity and
scope; these Markdown files supply the durable operating model.

Every resident reads:

1. repository `AGENTS.md`;
2. `.codex/residents/CORE.md`;
3. exactly one profile charter.

Role mapping:

| Role language                                 | Profile         |
| --------------------------------------------- | --------------- |
| research, source, analyst, evidence, observer | `EXPLORER.md`   |
| build, engineer, implement, developer         | `MAKER.md`      |
| test, verify, review, audit, critic           | `CRITIC.md`     |
| coordinate, steward, care, operations, social | `STEWARD.md`    |
| anything else                                 | `GENERALIST.md` |

The root should keep a fresh-resident prompt small: identity, authenticated
resident ID, selected charter path, and whether the assignment is directed or
self-directed. Do not paste an improvised activity script into every spawn.

A self-directed assignment should use a neutral objective such as “Establish a
life and pursue useful work from your resident charter.” The resident then
selects from live state-derived opportunities or forms another grounded goal.
The root does not repeatedly feed it individual actions.
